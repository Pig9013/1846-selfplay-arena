# 1846 Self-Play Arena 1.3.0 — Release Notes

> Released: 2026-10-28  
> Baseline: **v1.2.0**  
> Theme: revenue-first track scoring, winner-margin learning, a playable human table, and actual use of CUDA / route-search profiling  
> Sources: the 2026-10-28 v1.3 session, commits, the 1003-game diagnostic and the live machine state.

---

## 0. In one sentence

v1.2.0 made self-play continuous and data-driven; v1.3.0 makes the track score revenue-first, makes the winner’s margin dominate training, puts a real human table in the browser, and uses the GPU where a GPU actually helps.

It does **not** pretend to have solved true W–E running, 4-train route length, or cross-holding. The measured gaps are below.

## 2. Why: the concrete problems from the sessions

1. **“The AI only runs short routes; 4/5/6-train range is wasted.”**  
   Added per-train stop statistics, raised train distance weight from 3 to 5, changed track scoring to revenue-first. 1003-game diagnostic: 4-train 3.14 stops (human 3.84), 5-train 4.37 (4.87), 6-train 5.45 (5.73). The 4-train is still the most wasted.

2. **“The AI looks rich through cross-holding, but operates badly.”**  
   Winner-margin weighting, exclusion of bankrupt/short games, and holdings diagnostics. 1003 games: 2.23 corps per invested player; 69.9% hold ≥2, 36.9% ≥3. Lower than v1.2’s 2.48/80.4%/48.9%, but still common.

3. **“The AI lays track randomly, avoids cities, upgrades meaningless segments, builds dead ends.”**  
   City vs plain upgrade split; plain +4, no payoff −20; bare stub −30; E/W only when one side already exists.

4. **“Almost no true W–E running; at most a few W–W.”**  
   Acknowledged as a company-level planning problem. Added `chicago_connector` / `zone_connector` personas and human E/W route examples, but E/W was still 41.9% in the 1003-game diagnostic — **not solved**.

5. **“The human entry is useless: the AI runs 300 actions before I can move.”**  
   New `/human.html`: 1 human + 2 random AI, only the human’s turn exposes candidates, one click per action, each choice logged for behavior cloning.

6. **“Why is CPU at 93% and GPU at 1%?”**  
   PyTorch was CPU-only. CUDA build now used for training/inference, with 8 ms request batching, batch 512 and 12 workers. Rules/candidates/route search remain Ruby CPU; the CPU load is the workload, not a misconfiguration.

7. **“The stop button does nothing.”**  
   External runs now stop via `train/STOP` + PID + `status.json`; tested.

8. **“No undo; private companies can only be bought for `$1`; the AI can force-buy mine.”**  
   Undo rebuilds from the checkpoint (AI replies roll back, BC sample dropped); private offers cover $1..printed value grouped per company; buying from another player needs consent (AI accepts ≥75% of printed value); AI never initiates a purchase of the human’s private.

## 3. Learning signal

Old: every player’s final-asset z had a similar weight, so “winning a bad game” could dominate.

New:

- rank by final assets;
- `margin = first − second`;
- `winner_weight = 1 + floor(margin / 500)`, capped at 20;
- winner gets that weight; other players keep 0.15;
- the latest 100 games’ winners get another ×2;
- bankrupt games and games with <200 non-pass actions are excluded;
- advantage, prior imitation and value regression all use the sample weight.

1003-game diagnostic: average winner margin `$1,257`, average weight `3.05`, max `16`. The weight is active; whether it suppresses cross-holding still needs a controlled batch.

---

## 4. Track scoring: current + next turn, not “touch an offboard”

v1.2 gave `+42 + 0.6×revenue` for an offboard and `−30` for facing one without connecting. That pushed every tile toward an offboard, while most intermediate tiles on a long E/W line should not touch one.

v1.3:

```
current = (new city revenue − old city revenue) + offboard revenue
next    = new city revenue ×0.35 + through edges ×7 + connected edges ×4
score   = 2 + city upgrade 26 / plain upgrade 4 + current×0.55 + next
        + offboard link 10 − offboard miss 8 + E/W completion 30
        + first E/W 8 + approach ×1
        − cost×0.42 − train reserve
        − plain upgrade without payoff 20 − bare stub 30
```

Key points:

- offboard link is only **+10**;
- facing an offboard without connecting is only **−8**;
- intermediate tiles earn from through/connected edges and new cities;
- city upgrade `+26`, plain upgrade `+4`, bare stub `−30`;
- E/W completion finally `+30` (briefly +4, raised after the 1003 diagnostic still showed 41.9%), only when one side already exists.

## 5. Human table

The human entry is now a table, not a candidate list:

- player cards: cash, value, shares, privates;
- hex board: tiles, cities, tokens, offboards;
- corporation cards: president, treasury, share price, trains, stations, ownership bar; privates for sale; train depot;
- bottom: game log + action dock;
- two-step action flow: type → grouped options/map → confirm;
- legal hexes highlighted; selected tile drawn as a ghost before confirmation;
- undo `撤回 (N)`: replay to the checkpoint, roll back AI replies, drop the BC sample;
- private purchases: $1..printed value, grouped by company; seller consent for another player (AI accepts ≥75% of printed value); AI never bids for the human’s private;
- full record: `runs/human/对局日志.txt` (Chinese line + raw engine lines) and `game.json` (full actions).

Human samples go to `train/human_data/*.jsonl`; `train/human_bc.py` can learn only from human-won games and save a separate checkpoint for evaluation.

## 6. Model / compute: 512 was tested and reverted

- Old: `torch 2.13.0+cpu`; GPU idle.
- Now: `torch 2.13.0+cu130`, RTX 5070 Ti, `device: cuda`; `nnserver` batches requests for 8 ms (max 64); training batch 512; 12 Ruby workers.
- 512-wide Net2Net expansion kept the step-270 192 function. Same-seed A/B:
  - earlier 30 games: 192 4 wins / 9 top-2 / avg 2171; 512 4 / 8 / 2134;
  - later saved 20-game pair: 192 3 / 5 / 2090; 512 2 / 3 / 1931.
- **No evidence 512 is better.** Live checkpoint reverted to 192 (now step 301); 512 kept at `train/checkpoints/512-step275.pt`; 1024 not attempted.
- GPU is still often at ~18% during training and 1% idle; rules/candidates/routes are CPU. That is the workload, not a missing CUDA call.

### Route search

- A representative game: `route_calls 58`, `route_ms 4,167`, `candidate_ms 13,429` (31% routes); another game only 7%.
- Adaptive budget: 24/0.8 s (≤2 trains), 40/1.2 s (≤4), 48/1.6 s (>4).
- Same position: `route_ms 4,167 → 1,237`, no timeouts; cached per action/company.

## 8. What 1.3.0 still does not solve

1. **True W–E running** — 41.9% vs human 98.8%; still a company-level planning problem.
2. **4-train length** — 3.14 vs 3.84 stops; the train is bought but the network is short.
3. **Cross-holding** — 2.23 corps, 69.9% ≥2, 36.9% ≥3; lower than v1.2, still common.
4. **512 / 1024** — 512 did not prove better; 1024 was not attempted.
5. **No MCTS** — engine states are expensive to clone; candidate ranking + prior distillation + advantage weighting replace tree search.
6. **Human BC is early** — the table produces real `(state, legal actions, human action)` samples, but there are not enough human wins to prove `human_bc.pt` beats the frequency prior.
7. **Bankruptcy 6.6%** — still above human; the C&O/growth train-cash problem is only partially addressed.

## 9. Upgrade and run

From 1.2.0:

1. Pull `v1.3.0` or `main`.
2. Keep the sibling `18xx-master`; the engine is not vendored.
3. Old 40-wide samples are filtered; use `python train/prune_data.py --keep 700 --apply` to control size.
4. The old 192 checkpoint remains valid; 512 is an experiment, not `latest.pt`.
5. Human table: `p1846/human_ui.rb`, `web/human_*`, `build_web.py`; after editing the front end run `python build_web.py` to regenerate `web/human.html`.

Continuous self-play:

```bat
python train\orchestrate.py --workers 12 --minutes 0 --train-every 6 --steps 120 --eval-every 300 --report-every 1000 --strategy-mode mixed --human-prior-weight 20
```

Analysis and pruning:

```bat
python train\analyze.py
python train\prune_data.py --keep 700 --apply
```

Human vs AI: `http://127.0.0.1:1846/human.html` (or the home page entry). The human bridge is on 1847, the arena on 1846.
