# 1846 自战平台 1.3.0 发布说明

> 发布日期：2026-10-28  
> 对比基线：**v1.2.0**  
> 版本定位：从“能持续自战”推进到“按收益修路、按冠军差额学习、人类可以坐下来下、GPU/路线搜索不再闲置”  
> 本文按 2026-10-28 的 v1.3 开发会话、提交记录、1003 局诊断报告和本机实际运行状态整理；不是只按提交标题复述。

---

## 0. 一句话

v1.2.0 解决了“AI 能不能一直跑、能不能从人类频率里学”；v1.3.0 解决的是“AI 修路是不是在算收益、学习是不是在学真正的赢家、人类能不能真的插进去下一盘，以及 GPU/路线搜索有没有被用起来”。

这一版没有假装解决所有问题：**E/W 真正贯通、4 车跑满、交叉持股**仍然是明显差距，下面把数字和边界都写清楚。

## 1. v1.2.0 → v1.3.0 一张表

| 维度 | v1.2.0（旧） | v1.3.0（新） |
| --- | --- | --- |
| 铺轨评分 | 外域接通 `+42 + 0.6×收入`，朝外不接 `−30`；E/W 补全 `+55` | **收益优先**：外域接通只 `+10`，朝外不接 `−8`；当前回合城市/外域收入 ×0.55，下一回合潜力（新城市/通过边/连通边）另计；E/W 补全最终 `+30` |
| 升级 | 任何升级基础分较高，普通路线也容易“见线就升” | 城市升级 `+26`；普通路线升级只 `+4`，无城市/外域收益再 `−20`；裸断头路 `−30` |
| 学习目标 | 每局按最终资产算 z，所有玩家样本参与 | **冠军主导**：冠军 `1 + floor((冠军−亚军)/500)`，封顶 20；败者 0.15；最近 100 局冠军再 ×2；破产/过短局过滤 |
| 席位策略 | 固定席位/纯 neural 为主 | 每局混合抽取：neural×5，balanced/growth/income/random 各 1；`chicago_connector`、`zone_connector` 各 0.5；growth 不再无脑 withhold |
| 人类入口 | 665 局频率先验 + 命令行人类席位 | 新增 **18xx.games 式网页人类桌**：1 人 + 2 AI、版图/公司/股市/车场/动作栏、合法格高亮、瓦片 ghost、撤回、私营价格梯度与卖方同意 |
| 人类数据 | 只有频率先验，没有完整 state/action | 人类席位写出 `train/human_data/*.jsonl`；`train/human_bc.py` 做 behavior cloning；网页局写完整 `runs/human/对局日志.txt` + `game.json` |
| 模型/算力 | 192 宽 MLP，CPU-only PyTorch | CUDA PyTorch、批处理推理、batch 512、12 worker；512 宽网络做过 A/B，**没有更好，已回退 192**；1024 未尝试 |
| 路线搜索 | 固定 48 条/1.6 秒 | 自适应：≤2 车 24 条/0.8 秒，≤4 车 40 条/1.2 秒，>4 车 48 条/1.6 秒；按 action/公司缓存 |
| 数据占用 | 1,726 局 / 1.81 GB，训练 buffer 1,200 | prune 目标 700 局 / 约 0.74 GB，buffer 600；当前训练继续写入后为 1,054 局 / 约 1.16 GB，`train/prune_data.py` 可再裁回 700 |
| 运维 | 停止键对外部训练不可靠；Python 在 C 盘 | `train/STOP` + PID + `status.json` 三层停止；Python/PyTorch/pip 缓存迁 D 盘，C 盘路径做 junction |
| 网页日志 | 18xx.games 日志缺私营分配等信息 | 本地人类局完整记录：私营买卖、指派、车站、分红、列车价格、中文说明 + 引擎原始行 |

## 2. 这一版为什么这么改：对话里实际指出的问题

v1.3 的改动不是凭空加功能，逐条对应开发会话里提出的现象：

1. **“AI 只跑很短的距离，4/5/6 车的优势没发挥”**  
   → 新增车辆停靠统计；把 train 距离权重从 3 提到 5；把铺轨从“贴外域”改为收益优先。1003 局诊断：4 车 3.14 站（人类 3.84），5 车 4.37（4.87），6 车 5.45（5.73）。4 车仍是最浪费的。

2. **“AI 靠交叉持股显得赚钱，实际经营很差”**  
   → 学习权重改为冠军差额主导；破产/过短局不进训练；报告新增持股结构。1003 局：有持股玩家平均 2.23 家，69.9% 持 ≥2，36.9% 持 ≥3；比 v1.2 的 2.48/80.4%/48.9% 有下降，但仍普遍。

3. **“AI 修路很随意，故意不连城市、升级无意义路段、造断头路”**  
   → 城市升级与普通升级分开；普通升级 `+4`，无收益再 `−20`；裸 stub `−30`；E/W 补全只对“已有一侧、再补另一侧”生效，不做无脑贴外域。

4. **“自战几乎没有真正 W-E 贯通，只有极少数 W-W”**  
   → 承认这是公司级路线规划问题，不是再加一个全局加分能解决。v1.3 加了 `chicago_connector` / `zone_connector` 两个执着型 persona，并把人类典型 E/W 路线写入 playbook；但 1003 局 E/W 仍只有 41.9%，**没有解决**。

5. **“人类入口等于没有，AI 一次跑 300 步，人插不进去”**  
   → 新增 `/human.html`：1 人 + 2 随机 AI，只有轮到你时才显示候选；点击才执行一步；每一步写 behavior-cloning 样本。

6. **“为什么 CPU 93%、GPU 1%？GPU 不是 AI 最常用的吗？”**  
   → 查清是 CPU-only PyTorch；换 CUDA 版后训练/推理上 GPU，推理批处理、batch 512、12 worker。但规则引擎/候选生成/路线搜索仍是 Ruby CPU，CPU 高是工作负载结构，不是配置错误。

7. **“停止键按了没用”**  
   → 外部训练也走 `train/STOP` + PID + `status.json`，实测能停。

8. **“人类桌没有撤回；收购私营只能 `$1`，且 AI 能强买我的公司”**  
   → 加撤回（连 AI 回应一起回退，删对应 BC 样本）；私营价格从 `$1` 到明面价值按公司分组；向其他玩家买需同意，AI 低于 75% 估值拒绝；AI 不主动买人类私营。

## 3. 学习信号：从“所有人”到“冠军差额”

旧版每局把所有玩家的最终资产标准化成 z，所有人都有相近权重。问题是：**一局里“比烂”也能产生看似不错的相对收益**，交叉持股/留存发展容易在低质量样本里胜出。

v1.3 改成：

- 每局按最终资产排名；
- `margin = 第一名 − 第二名`；
- `winner_weight = 1 + floor(margin / 500)`，封顶 20；
- 冠军样本用 `winner_weight`，其他玩家只保留 **0.15** 的小权重；
- 最近 **100 局**的冠军再乘 **2**，避免新风格被旧样本淹没；
- 破产局、非 pass 行动 <200 的过短局不进训练；
- 策略优势、先验模仿、价值回归都乘这个样本权重。

1003 局诊断：冠军对亚军平均差额 **$1,257**，平均学习权重 **3.05**，最高 **16**。这证明权重在生效，但还不能证明“交叉持股已被压下去”——需要下一批对照。

## 4. 铺轨：从“贴外域”到“当前 + 下一回合收益”

v1.2 的铺轨评分把外域接通给到 `+42 + 0.6×收入`，朝外不接 `−30`。这会把 AI 逼成“每块瓦都要贴着外域”，而一条 E/W 长线中间的大量格子本来就不该连外域。

v1.3 改成：

```
当前回合收益 = (新城市收入 − 旧城市收入) + 接通外域的收入
下一回合潜力 = 新城市收入 ×0.35 + 通过边 ×7 + 连通边 ×4
铺轨分 = 2 + 城市升级26/普通升级4 + 当前收益×0.55 + 下一回合潜力
        + 外域接通10 − 朝外不接8 + E/W补全30 + 首次E/W8 + 靠近缺失侧×1
        − 成本×0.42 − 列车储备
        − 普通升级无收益20 − 裸 stub 30
```

关键变化：

- 外域接通只值 **+10**，不再是几十上百；
- 朝向外域没接通只扣 **−8**，不再一票否决；
- 长线中间的普通格子，靠“通过边/连通边/新城市”拿分；
- 城市升级 `+26`，普通升级 `+4`，裸断头路 `−30`；
- E/W 补全最终 `+30`（中间曾降到 +4，1003 局显示 E/W 仍 41.9% 后又提高），只对“已有一侧、再补另一侧”生效。

## 5. 人类桌：不是“能点”，而是按 18xx.games 的方式下

v1.3 把人类入口从“候选列表”重做成一张 18xx.games 风格的桌子：

- 左侧玩家：现金、总资产、持股、私营；
- 中间版图：六角格、瓦、城市、车站、外域；
- 右侧公司：总裁、金库、股价、列车、车站、股权条；待售私营；车场；
- 下方：对局记录 + 行动区；
- 行动三步：行动类型 → 分组选项/地图 → 确认；
- 铺轨/设站时合法格高亮；选瓦片后地图上画 ghost，确认前能看到线路、城市、收入；
- 撤回 `撤回 (N)`：按记录 action 重放到检查点，连 AI 回应一起回退，删该步 BC 样本；
- 私营收购：`$1` 到明面价值按公司分组；向其他玩家买需同意，AI 低于 75% 估值拒绝；AI 不主动买人类私营；
- 完整记录：`runs/human/对局日志.txt`（中文说明 + 引擎原始行）与 `game.json`（完整 action）。

人类数据写到 `train/human_data/*.jsonl`，`train/human_bc.py` 可以只学“人类获胜局”的每一步，存成单独 checkpoint，先评估再决定是否混入自战。

## 6. 模型/算力：512 试过，但 A/B 没证明更好

- 旧：`torch 2.13.0+cpu`，GPU 完全不动。
- 现在：`torch 2.13.0+cu130`，RTX 5070 Ti，`device: cuda`；`nnserver` 8ms 合并请求、最大 batch 64；训练 batch 512；12 个 Ruby worker。
- 512 宽网络用 Net2Net 扩展，保留 step 270 的 192 函数；A/B 同种子：
  - 较早 30 局：192 胜 4 / 前二 9 / 均分 2171；512 胜 4 / 前二 8 / 均分 2134。
  - 后来保存的 20 局配对：192 胜 3 / 前二 5 / 均分 2090；512 胜 2 / 前二 3 / 均分 1931。
- 结论：**没有证据 512 更好**。live checkpoint 回退到 192（当前 step 301）；512 保留在 `train/checkpoints/512-step275.pt`；1024 未尝试。
- GPU 平均利用率仍低（训练时约 18%，空闲 1%），因为规则/候选/路线搜索是 CPU；这不是“没调用 GPU”，是工作负载类型不同。

### 路线搜索 profile 与自适应预算

- 代表性一局：`route_calls 58`、`route_ms 4,167`、`candidate_ms 13,429`，路线占 31%；另一局只占 7%。
- 自适应预算：≤2 车 24 条/0.8 秒，≤4 车 40 条/1.2 秒，>4 车 48 条/1.6 秒。
- 同类局面 `route_ms 4,167 → 1,237`，无超时；按 action/公司缓存路线结果。

## 8. 这一版仍然没做好的地方

1. **真正的 W-E 贯通仍然没有解决。** 1003 局只有 41.9% 出现 E/W 奖励，人类 98.8%。原因还是公司级路线规划：AI 不会先决定“由 GT/IC/NYC/B&O 其中一家从 C17 修到 C5”，再把现金、股份、铺轨槽位倾斜过去。
2. **4 车仍只跑 3.14 站（人类 3.84）。** 车买了，线路不够长；不是再加一个 train 权重能解决。
3. **交叉持股仍普遍。** 2.23 家/69.9% ≥2/36.9% ≥3，比 v1.2 低，但还远未消失。
4. **512 没有证明更好，1024 没有尝试。** 模型容量不是当前瓶颈；CPU 生成数据才是。
5. **没有 MCTS。** 1846 局面克隆太贵，当前是“候选排序 + 先验蒸馏 + 优势加权”。
6. **人类 BC 样本还少。** 人类桌能产出真正的 `(state, legal actions, human action)`，但还没有足够胜局证明 `human_bc.pt` 比频率先验更强。
7. **破产率 6.6%** 仍高于人类，C&O/growth 的列车现金问题只做了局部修复。

## 9. 升级与运行

### 从 1.2.0 升级

1. 拉取 `v1.3.0`（或 `main`）。
2. 保留同级 `18xx-master`；仓库不内置规则引擎。
3. 旧 `train/data` 的 40 维样本会被训练器过滤；建议用 `python train/prune_data.py --keep 700 --apply` 控制体积。
4. 旧 192 checkpoint 可以继续用；512 checkpoint 只作实验，不设为 `latest.pt`。
5. 人类桌新增 `p1846/human_ui.rb`、`web/human_*`、`build_web.py`；改前端后运行 `python build_web.py` 重新生成单文件 `web/human.html`。

### 持续自战

```bat
python train\orchestrate.py --workers 12 --minutes 0 --train-every 6 --steps 120 --eval-every 300 --report-every 1000 --strategy-mode mixed --human-prior-weight 20
```

### 生成当前分析

```bat
python train\analyze.py
python train\prune_data.py --keep 700 --apply
```

### 人类 vs AI

打开 `http://127.0.0.1:1846/human.html`（或首页「人类与 AI 作战」）。人类桥接在 1847，平台在 1846；首次启动需要平台服务在跑。
