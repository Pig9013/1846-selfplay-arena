# 1846 Self-Play Arena · лаборатория самоигры 1846

Локальная платформа самоигры и самообучения для **1846: The Race for the Midwest**: правила исполняет открытый движок 18xx.games, а платформа даёт ботов с пониманием правил, цикл обучения на самоигре с нейросетью, веб-интерфейс наблюдения с повтором и набор инструментов аудита, сверяющий значения правил с журналами реальных партий.

[![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**Версия 1.2.0** · Windows · работа офлайн · без аккаунта на сайте и без облачной модели

> **Что нового в версии 1.2.0**: непрерывная самоигра с 316 пригодными партиями, 48-мерные признаки действий и ограниченная нейросетевая поправка, оценка прокладки с учётом поворота, приор из 665 человеческих партий вместо жёстко заданного Чикаго, анализ каждые 1000 партий. Полное сравнение: [RELEASE_NOTES.en.md](RELEASE_NOTES.en.md).

## Какую задачу решает проект

Детали правил 18xx (стоимость местности, доход оффборда, меняющийся по фазам, бонусы восток–запад, тайлы только для Z/Чикаго, блокировка станциями, запас тайлов) очень легко сделать неправильно в самодельном ИИ. Проект отдаёт «правила» движку, проверенному в реальных партиях на сайте, оставляет «решения» себе и сверяет реализацию правил с **журналами реальных партий**:

- **Исполнение правил**: `18xx-master` (tobymao/18xx, MIT) — единственный арбитр; боты лишь порождают кандидатов, а движок их проверяет.
- **Аудит реальных партий**: `audit/` выгружает из движка каталог тайлов, воспроизводит прокладку пути, фазы и распределение бонусов по 95 журналам 18xx.games и независимо пересчитывает **69 494 дохода маршрутов**, совпадая с записями сайта на **99,99 %**.
- **Цикл самообучения**: минимальная реализация в духе KataGo — многопроцессная выборка самоигры → обучение сети политики и ценности → горячая перезагрузка новой модели → оценка доли побед против эвристических баз.
- **Наблюдаемость**: веб-страница в реальном времени показывает поле, стоимости, значения оффборда, атрибуцию бонусов, запас тайлов и слоты прокладки/апгрейда на каждый ход.

> 1846 — игра Thomas Lehmann, издатель GMT Games. Репозиторий **не содержит** правил, графических материалов и любых официальных файлов; движок правил — сторонний код под MIT, а данные самоигры порождают боты этого проекта.

## Основные возможности

| Модуль | Описание |
| --- | --- |
| Значения правил | Стоимость прокладки = max($20, напечатанное значение); плата за ребро реки/горы/тоннеля взимается при **первом соединении**; тайлы Z / чикагские / обычные разделены; число тайлов ограничено; заполненная станция блокирует проход |
| Оффборд и восток–запад | Доход оффборда берётся по фазе (жёлтая/коричневая); E→E запрещено, W→W разрешено, Holland и Louisville нейтральны; бонус E/W — сумма значений значков оффборда на обоих концах |
| Частные компании | Boomtown / Meat Packing / Steamboat действуют по **гексу** и по **владельцу** (пристани Wheeling/Holland +$40, остальные +$20); распределение и атрибуция видны |
| Боты | Генерация кандидатов с учётом правил (проверка связности, запас тайлов, цвет/зарезервированный путь, ограничения по акциям и поездам), эвристическая оценка, опционально поверх неё — политика нейросети |
| Самообучение | `p1846/selfplay.rb` сэмплирует → `train/nnserver.py` выводит → `train/trainer.py` обучает → `train/orchestrate.py` оркестрирует непрерывно → `train/analyze.py` анализирует каждые 1000 партий |
| Человеческий приор | `train/human_playbook.py` создаёт `human_playbook.md` и `human_prior.json` из 665 человеческих партий; `p1846/human_prior.rb` использует их как мягкий приор, а не как правило |
| Анализ | `train/analyze.py` пишет `train/reports/logic-N.md`: структура действий, доля принятия 1-го кандидата, Чикаго/C5/Z, корреляции побед, сравнение ИИ с 665 людьми, список следующих исправлений |
| Наблюдение | Локальная веб-страница: поле, повтор, активы игроков, таблица корпораций, причины решений, панель обучения |
| Аудит | `audit/log_audit.py` пересчитывает доходы маршрутов по реальным журналам; `verify_game.rb` воспроизводит ход за ходом и проверяет сохранение суммы денег |
| Ресурсы | Дочерние процессы работают ниже обычного приоритета; параллелизм по умолчанию «ядра − 2»; обучение использует только 2 потока torch |

## Быстрый старт

### Требования

- Windows 10/11, Python 3.12 (платформа работает на одной стандартной библиотеке; для обучения нужен PyTorch)
- В проекте есть портативная среда Ruby 3.4.9 в `runtime/` (системный Ruby не изменяется)
- **Движок правил 18xx** кладётся **рядом** с этим каталогом: `../18xx-master` (клонируйте `https://github.com/tobymao/18xx` или используйте уже имеющийся снимок)

```
父目录/
├── 1846自战平台/      ← 本仓库
│   ├── server.py
│   ├── arena.rb
│   ├── p1846/
│   ├── train/
│   ├── audit/
│   ├── web/
│   └── runtime/        ← Ruby 运行时（发布包自带，仓库中忽略）
└── 18xx-master/        ← 规则引擎（MIT）
```

### Запуск платформы

```bat
启动平台.cmd
```

Откройте `http://127.0.0.1:1846` в браузере, выберите число игроков и стратегии мест, затем запустите самоигру. Можно и так:

```bat
python server.py --no-browser --port 1846
```

### Запуск самообучения

```bat
python train\orchestrate.py --workers 6 --minutes 0 --train-every 4 --steps 200 --eval-every 300 --report-every 1000
```

Или дважды щёлкните `启动训练.cmd`. Модели пишутся в `train/checkpoints/latest.pt`, выборки — в `train/data/`, а панель «Самообучение» на веб-странице позволяет запускать и останавливать процесс.

### Проверка правил

```bat
ruby audit\export_catalog.rb     :: 从引擎导出瓦片目录
python audit\log_audit.py        :: 重算真实日志的线路收入并比对
python verify_all.py runs        :: 逐局重放并核对收入与现金守恒
python tests\\test_audit.py       :: 审计器单元测试（CI 也跑这个）
```

## Форматы данных

### Партии (`examples/selfplay/*/game.json`)

Формат движка 18xx: игроки, сид, полный `raw_actions`. Его можно воспроизвести напрямую через `verify_game.rb`:

```bat
ruby verify_game.rb "examples\selfplay\4p-seed606\game.json"
```

### Обучающие выборки (`examples/training/*.jsonl.gz`)

Один JSONL на партию, построчно:

```json
{"type":"decision","actor":"1","state":[128 个浮点],"actions":[[40 个浮点],...],"chosen":0,"prior":[...]}
{"type":"result","scores":{"1":5506,"2":0,...},"z":{"1":0.98,...}}
```

- `state`: признаки позиции (фаза, банк, деньги/поезда/цена акций корпораций, активы игроков, статистика поля)
- `actions`: признаки действий не более 12 легальных кандидатов в этой точке решения
- `chosen`: индекс фактически выполненного кандидата
- `prior`: эвристическая оценка (для дистилляции)
- `z`: ранговый выигрыш, нормированный по итоговым активам (среднее 0, стандартное отклонение 1)

## Результаты проверки правил

Пересчитано 95 журналов и 69 494 дохода маршрутов, совпадение с сайтом — **99,99 %** (5 расхождений вызваны пропусками в отслеживании поля самим аудитором). В ходе аудита подтверждены и исправлены две реализации, в которых легко ошибиться:

- **Mail Contract** берёт плату по **пройденным** станциям (включая станции, которые пропускают поезда N/M, и станции, не приносящие дохода);
- **Значки портов «липкие»**: после апгрейда города значок порта сохраняется до события фазы IV, снимающего бонус.

Фактическое распределение стоимостей прокладки тоже совпадает с правилом 6.48: H16 — $40 за первую прокладку / $20 за апгрейд; B16 — $20 без пересечения горного ребра и $60 с ним; I11 — $60 за переход через реку; F18 даёт комбинации 20/40/60/80.

## Состояние самообучения (1.2)

Последний снимок (2026-10-28 14:58, `train/reports/logic-0318.md`): **316 пригодных партий, 182 549 решений, 0 вырожденных партий**; 96,8% зелёного Чикаго, 93,7% всех трёх городов Z, 89,9% хотя бы один C5, 35,8% E/W, 8,9% банкротств.

- **Непрерывная самоигра**: 6 процессов до остановки; каждая партия пишет `train/games.jsonl` и `train/data/`; отчёт `train/reports/logic-N.md` каждые 1000 партий.
- **Человеческий приор (1.2)**: частоты 665 человеческих партий дают `human_playbook.md` и `human_prior.json`; политика использует их как мягкий приор (по умолчанию 10, 0 отключает).
- **Чикаго (1.2)**: жёсткие бонусы v1.1 (D6 +30/+55/+90/+125, C5 +40, станция Чикаго +58, расстояние от дома) удалены. Чикаго появляется только через общий доход, связность и человеческий приор; 96,8% зелёного Чикаго — результат обучения, а не запись в скоринге.
- **E/W (1.2)**: соединение второй стороны +55, первой +14, приближение к недостающей стороне +2 за гекс; связи с Чикаго нет.
- **Главный разрыв**: E/W 35,8% против 98,8% в 665 человеческих партиях. Причина — планирование на уровне компании: IC идёт только на W, GT/ERIE/NYC/PRR/B&O — только на E, ни одна компания не связывает обе стороны.
- **MCTS нет**: позиции движка нельзя дёшево клонировать, поэтому используются ранжирование кандидатов + дистилляция приоров + взвешивание по преимуществу.
- **Доля побед**: всего 2 оценочные партии, 0 побед. Выборка слишком мала, чтобы судить сеть, тем более утверждать превосходство над людьми.

## Известные ограничения

- Только стандартная 1846, 3–5 игроков, без опциональных правил.
- Кандидаты ботов покрывают не все особые способности (прокладка пути некоторыми частными компаниями, обмен поездами).
- Веб-поле — упрощённый рисунок на основе данных: значения, ориентация и смежность соответствуют правилам, но это не официальная графика.
- Полную последовательность действий реальных партий нельзя получить через API сайта (архивные партии возвращают пустые actions), а локальные журналы скрывают этап распределения частных компаний, поэтому аудит работает по «полю + пересчёту доходов», а не по полному воспроизведению партии.
