# 1846 Self-Play Arena · 1846 自己対戦ラボ

**1846: The Race for the Midwest** の自己対戦／自己学習をローカルで回すプラットフォーム：ルールは 18xx.games のオープンソースのルールエンジンが実行し、ルールを意識したボット、ニューラルネットによる自己対戦訓練ループ、リプレイ可能なウェブ観戦画面、実対局ログでルール数値を検証する監査ツールを提供する。

[![verify](https://github.com/Pig9013/1846-selfplay-arena/actions/workflows/verify.yml/badge.svg)](https://github.com/Pig9013/1846-selfplay-arena/actions/workflows/verify.yml)
[![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**バージョン 1.2.0** · Windows · オフライン動作 · サイトのアカウントもクラウドモデルも不要

> **バージョン 1.2.0 の新機能**：316 局の有効な自己対戦、48 次元の行動特徴と有界なニューラル残差、回転を考慮した敷設評価、665 局の人間対局による事前分布（シカゴのハードコードを置換）、1000 局ごとの分析。詳細は [RELEASE_NOTES.en.md](RELEASE_NOTES.en.md)。

---

## このプロジェクトが解く問題

18xx のルールの細部（地形費用、フェイズで変わるオフボード収入、東西ボーナス、Z／シカゴ専用タイル、駅による遮断、タイル在庫）は、自作 AI では間違えやすい。本プロジェクトは「ルール」をサイトの実戦で検証済みのエンジンに任せ、「意思決定」を自分側に残し、**実対局ログ**でルール実装が正しいかを突き合わせる：

- **ルール実行**：`18xx-master`（tobymao/18xx、MIT）を唯一の裁定者とし、ボットは候補を出すだけで、最終的な検証はエンジンが行う。
- **実対局の監査**：`audit/` がエンジンからタイル目録を書き出し、95 件の 18xx.games ログの敷設／フェイズ／ボーナス配分を再現して、**69,494 件の路線収入**を独立に再計算し、サイトの記録との一致率は **99.99%** である。
- **自己学習ループ**：KataGo 方式の最小実装——マルチプロセスの自己対戦サンプリング → 方策／価値ネットワークの訓練 → 新モデルのホットリロード → ヒューリスティックなベースラインとの勝率評価。
- **観測可能**：ウェブ画面が盤面、費用、オフボード数値、ボーナス帰属、タイル在庫、ターンごとの敷設／昇格スロットをリアルタイムに表示する。

> 1846 は Thomas Lehmann の設計、GMT Games の出版による作品である。本リポジトリはルールブック、アート素材、その他の公式ファイルを**一切含まない**。ルールエンジンは第三者による MIT コードであり、自己対戦データは本プロジェクトのボットが生成したものである。

## 主な機能

| モジュール | 説明 |
| --- | --- |
| ルール数値 | 敷設費用 = max($20, 印刷値)。川／山／トンネルの辺費用は**初回接続**時に支払う。Z タイル／シカゴ用タイル／通常タイルは区別される。タイル枚数には上限がある。駅が埋まると通過を遮断する |
| オフボードと東西 | オフボード収入はフェイズ（黄／茶）ごとの値を使う。E→E は不可、W→W は可、Holland と Louisville は中立。E/W ボーナスは両端のオフボードアイコンの値の合計 |
| プライベートカンパニー | Boomtown / Meat Packing / Steamboat は**ヘクス**ごと、**所有者**ごとに作用する（Wheeling/Holland の港は +$40、それ以外は +$20）。配分と帰属は画面で確認できる |
| ボット | ルールを意識した候補生成（接続検査、タイル在庫、色／予約済み軌道、株式と列車の制限）、ヒューリスティックな採点、ニューラルネット方策の重ね掛けが可能 |
| 自己学習 | `p1846/selfplay.rb` がサンプリング → `train/nnserver.py` が推論 → `train/trainer.py` が訓練 → `train/orchestrate.py` が継続的に編成 → `train/analyze.py` が 1000 局ごとに分析 |
| 人間の事前分布 | `train/human_playbook.py` が 665 局の人間対局から `human_playbook.md` と `human_prior.json` を生成；`p1846/human_prior.rb` はルールではなくソフトな事前分布として使う |
| 分析 | `train/analyze.py` が `train/reports/logic-N.md` を書く：行動構成、第 1 候補の採用率、シカゴ/C5/Z、勝敗相関、AI 対 665 局の人間、次の修正リスト |
| 観戦 | ローカルウェブ画面：盤面、リプレイ、プレイヤー資産、会社一覧、意思決定の理由、訓練パネル |
| 監査 | `audit/log_audit.py` が実ログから路線収入を再計算し、`verify_game.rb` が 1 行動ずつ再生して現金の保存を検査する |
| 資源使用 | 子プロセスは通常より低い優先度で動く。並列度の既定値は「コア数 − 2」。訓練は torch スレッドを 2 本だけ使う |

## クイックスタート

### 必要なもの

- Windows 10/11、Python 3.12（標準ライブラリだけでプラットフォームは動く。訓練には PyTorch が必要）
- 本プロジェクトは Ruby 3.4.9 のポータブルランタイムを `runtime/` に同梱する（システムの Ruby は変更しない）
- **18xx ルールエンジン**は本ディレクトリの**隣**に置く：`../18xx-master`（`https://github.com/tobymao/18xx` を clone するか、手持ちのスナップショットを使う）

```
父目录/
├── 1846自战平台/      ← 本仓库
│   ├── server.py
│   ├── arena.rb
│   ├── p1846/
│   ├── train/
│   ├── audit/
│   ├── web/
│   └── runtime/        ← Ruby 运行时（发布包自带，仓库中忽略）
└── 18xx-master/        ← 规则引擎（MIT）
```

### プラットフォームの起動

```bat
启动平台.cmd
```

ブラウザで `http://127.0.0.1:1846` を開き、人数と席の戦略を選んで自己対戦を開始する。次の方法もある：

```bat
python server.py --no-browser --port 1846
```

### 自己学習の実行

```bat
python train\orchestrate.py --workers 6 --minutes 0 --train-every 4 --steps 200 --eval-every 300 --report-every 1000
```

または `启动训练.cmd` をダブルクリックする。モデルは `train/checkpoints/latest.pt`、サンプルは `train/data/` に書き出され、ウェブの「自己学習トレーニング」パネルから開始／停止できる。

### ルールの検証

```bat
ruby audit\export_catalog.rb     :: 从引擎导出瓦片目录
python audit\log_audit.py        :: 重算真实日志的线路收入并比对
python verify_all.py runs        :: 逐局重放并核对收入与现金守恒
python tests\\test_audit.py       :: 审计器单元测试（CI 也跑这个）
```

## データ形式

### 対局（`examples/selfplay/*/game.json`）

18xx エンジンの形式：プレイヤー、シード、完全な `raw_actions`。`verify_game.rb` でそのまま再生できる：

```bat
ruby verify_game.rb "examples\selfplay\4p-seed606\game.json"
```

### 訓練サンプル（`examples/training/*.jsonl.gz`）

1 局につき 1 つの JSONL で、各行は次のとおり：

```json
{"type":"decision","actor":"1","state":[128 个浮点],"actions":[[40 个浮点],...],"chosen":0,"prior":[...]}
{"type":"result","scores":{"1":5506,"2":0,...},"z":{"1":0.98,...}}
```

- `state`：局面特徴（フェイズ、銀行、会社の現金／列車／株価、プレイヤー資産、盤面統計）
- `actions`：その意思決定点における最大 12 個の合法候補の行動特徴
- `chosen`：実際に実行した候補の添字
- `prior`：ヒューリスティックな採点（蒸留に使用）
- `z`：最終資産で正規化した順位報酬（平均 0、標準偏差 1）

## ルール検証の結果

95 件のログ、69,494 件の路線収入を再計算し、サイトとの一致率は **99.99%**（5 件の差異は監査器自身の盤面追跡の取りこぼしに由来する）。監査の過程で、間違えやすい実装を 2 件確認して修正した：

- **Mail Contract** は**経由**した駅で課金する（N/M 列車が飛ばす駅、収入を生まない駅も含む）。
- **港アイコンは粘着する**：都市が昇格しても、フェイズ IV のボーナス除去イベントまで港アイコンは残る。

敷設費用の実測分布もルール 6.48 と一致する：H16 は初回敷設 $40／昇格 $20、B16 は山の辺を越えなければ $20、越えれば $60、I11 は川を越えて $60、F18 では 20/40/60/80 の組み合わせが現れる。

## 自己学習の現状（1.2）

最新スナップショット（2026-10-28 14:58、`train/reports/logic-0318.md`）：**316 局が利用可能、182,549 意思決定、退化 0 局**。緑シカゴ 96.8%、Z 三都市すべて 93.7%、C5 一度以上 89.9%、E/W 35.8%、破産 8.9%。

- **継続自己対戦**：6 プロセスが停止まで実行；各局は `train/games.jsonl` と `train/data/` に書き込み；1000 局ごとに `train/reports/logic-N.md`。
- **人間の事前分布（1.2）**：665 局の人間対局の頻度から `human_playbook.md` と `human_prior.json` を生成；方策はソフトな事前分布として扱う（既定 10、0 で無効）。
- **シカゴ（1.2）**：v1.1 のハードコード（D6 +30/+55/+90/+125、C5 +40、シカゴ駅 +58、本拠地からの距離）を削除。シカゴは汎用収入・接続性・人間の事前分布だけから現れる。緑シカゴ 96.8% は学習結果であり、スコアに書き込んだものではない。
- **E/W（1.2）**：反対側への接続 +55、最初の片側 +14、欠けた側への接近は 1 ヘクス +2。シカゴとは結合しない。
- **最大の差**：E/W 35.8%（人間 665 局は 98.8%）。原因は会社レベルの路線計画：IC は W のみ、GT/ERIE/NYC/PRR/B&O は E のみを走り、両側を結ぶ会社がない。
- **MCTS なし**：エンジン局面を安価に複製できないため、候補の順位付け + 事前分布の蒸留 + アドバンテージ重み付けで代替する。
- **勝率**：評価は 2 局のみ、0 勝。標本が小さすぎてネットワークを評価できず、人間を上回るとは言えない。

## 既知の制限

- 標準 1846、3–5 人、オプションルールなしのみを扱う。
- ボットの候補はすべての特殊能力を網羅していない（一部のプライベートカンパニーによる敷設、列車の売買）。
- ウェブ盤面はデータ駆動の簡略描画であり、数値・方位・隣接はルールと一致するが、公式アートではない。
- 実対局の完全な行動列はサイトの API から取得できず（アーカイブ済み対局は空の actions を返す）、ローカルログもプライベートカンパニーの配分段階を隠すため、監査は「盤面 + 収入の再計算」で行い、全局の再生はしない。
